# MCPack Policy Gateway POC - PRD Traceability Matrix

## Scope and evidence

This matrix compares the implemented repository against:

- the original 28-page **MCPack Product Requirements Document, V1** supplied as `C:\Users\86153\Desktop\MCPack POC PRD.pdf`;
- `docs/implementation-plan.md`;
- `AGENTS.md`;
- all files under `src/`; and
- all automated tests under `test/` and `tests/`.

`docs/PRD.pdf` was requested as the source path but is not present in this repository. The original desktop PDF named above is therefore the PRD source used for this matrix.

The implementation contains two related but currently separate surfaces:

1. the published MCPack discovery/RBAC library in `src/core.ts`, `src/wrap.ts`, and `src/build.ts`; and
2. the local HTTP Policy Gateway POC in `src/app.ts` and the `policy`, `gateway`, `approval`, `audit`, `http`, and `tools` modules.

The status values mean:

- **complete** - implemented for the current POC interpretation and directly tested;
- **partial** - meaningful implementation exists, but an important part of the POC interpretation or PRD acceptance behavior is absent;
- **excluded** - intentionally outside the first POC under `AGENTS.md` or the implementation plan;
- **missing** - expected by the first demonstrable POC or its acceptance criteria, but not implemented.

## Genuine gaps versus deliberate exclusions

### Genuine gaps in the first demonstrable POC

The following are described as part of the implementation plan's first POC promise or acceptance criteria and are not merely future production features:

1. A return-policy/redaction engine is absent; tool responses leave the gateway unchanged.
2. The new Policy Gateway is not integrated into real MCP wrap/build call paths.
3. Original requester and acting agent are not independently resolved, and workflow/tool-call correlation IDs are absent.
4. Approval detail has no safe-review projection and can return stored arguments directly.
5. The demo does not show rejection or output redaction, and audit coverage omits several attempted/failure transitions.
6. `policy.json` loading and startup validation are absent.

### Intentionally excluded future requirements

These omissions are consistent with `AGENTS.md` and the implementation plan and should not be classified as POC defects:

- production authentication and identity-provider integration;
- A2A delegation policy and multi-hop workflows;
- SQL/query-safety analysis;
- dashboards and policy-administration UI;
- external databases, queues, notifications, and real external side effects;
- tamper-evident/immutable ledger storage; and
- production durability, availability, and compliance claims.

## Overall assessment

The repository demonstrates a credible local vertical slice for deterministic allow/deny/approval decisions, guarded mock execution, in-memory approval state, duplicate-execution protection, and replaceable sanitized audit delivery. It does **not yet demonstrate the complete PRD/implementation-plan promise** because governed output redaction and shared real-MCP enforcement are missing, while identity/custody attribution remains a flat, untrusted HTTP context rather than a resolved workflow model.
